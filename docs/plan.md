# MS-RetrieveGuard 实施计划

批准日期：2026-10-22。基线 commit：`65f5a613d5399601f2e1dc3d8e6495432ba0b65f`。
本文件保存用户批准的研究协议；运行状态见 `status.md`，研究来源见 `evidence.jsonl`。
计划中的模型、耗时和样本量不是已完成实验的证据。当前只授权首先完成下述首个实施包，之后依阶段验收推进，不为维持原题目增加复杂模块。

## 研究目标与创新门槛

研究固定检索器下，选择分数和冻结阈值在候选机制变化时的可靠性。必须在同一分子队列、同 K、同检索器与候选得分下，排除候选捷径后，验证稳健训练是否比强简单选择器有实际收益。

置信度、拒识、SGR、条件共形预测、缺真值、大候选库、困难候选及数据库缺真值误注释均已有先例。普通/稳健选择器和统计并集界不是新理论；若强简单基线已经解决问题，停止该方法路线，保存负面结果。冻结底座和对齐头也不是新贡献。

## 数据、封存与候选协议

- 主数据固定为 `roman-bushuiev/MassSpecGym` revision `d2e86d0c3bd905a6d578c0dd6053ed2bd41f9c2a`；首批仅 `MassSpecGym1.5.tsv` 与 v1.5 formula candidates，下载元数据合计约 631.5 MB，须本地完整校验。
- 数据库平台 `split=val` 是容器名；官方部分来自 TSV 内部 `fold`，不得将整个容器当 validation。原文 194,119/19,429/17,556 是谱图数声明，validation 3,185 是分子数声明，均须本地重算。
- 真值和候选使用相同标准化；固定 RDKit/InChI 版本，二维身份以标准化后 InChIKey 前14位分组，保留电荷，不默认中和或取最大碎片。解析失败、多组分及身份/质量冲突隔离并报告，不能静默丢弃。
- 保留官方 train/test；validation 按分子确定性划为 `dev_ranker/fit_selector/calibration/pilot_dev = 15/25/40/20`。划分种子和模型种子分开。跨官方部分身份交集统一隔离，不移动到可开发部分。
- 同一查询分子的全部谱图、候选变体和 present/absent 版本保持同角色。候选结构跨角色复用单独记为结构暴露，不把它等同于谱图—结构标签泄漏。
- 主统计预先确定每分子一张谱图；全谱图结果单列，bootstrap 按分子聚类。不能通过谱图、变体或种子扩大独立样本量。
- **前十四个开发日 calibration 与 test 封存**。只允许身份、split、泄漏、暴露、候选合法性和样本量审计；模型得分、嵌入、检索指标、选择器拟合和阈值调参均禁止。第13–14天也不例外。封存起点、时区和解封条件持久化，不因换会话重置。
- 已知分子式和测量质量属于不同信息条件，独立报告。质量路线不能把真实中性质量作为部署输入。
- 对每个 K 原池须含真值及至少 K 个不同合法负身份。present/absent 共享 K−1 个负候选，分别加入真值/额外负候选；absent 移除全部真值等价体。候选不足统一过滤并报告保留比例。
- 主 K 按性能无关保留表从128、64、32依次选择；目标至少800 cal、300 pilot、400 selector-fit、200 ranker-dev分子。达不到时明确降为小样本经验研究，不作正式认证能力声明。跨 K 分析同时报共同分子队列和全部合法队列。
- 固定机制 U（合法池均匀）、H（真值 Morgan 相似度困难候选，离线压力测试）、D（候选间指纹距离 farthest-first）。U/H开发；D先固定规则，阶段4前只审计合法性与数量，不看模型表现。不能把训练/开发已见 H 机制称为未见机制。
- 候选排列、序号、SMILES格式不能编码标签；身份标签不依赖指纹相等、候选第零位或随机 epsilon 平局处理。

## 最小实现与统计接口

- 实现小型 Python 包与 `python -m ms_retrieve_guard` CLI；以 `configs/pilot.yaml` 保存首包配置。环境、下载、临时文件、权重、缓存全部在数据盘 `artifacts/`，始终调用项目环境 Python 绝对路径。
- MLP 首选 ms-mole 配方：0.1 Da 分箱至1005，10,050维输入，1024宽度，4096位 Morgan r2，显式 `list_fp_cos`。Adam、学习率 `1e-4`、batch64、FP32；正式单种子最多50轮且受GPU预算约束，只用 `dev_ranker` R@1 选 checkpoint。小规模闭环不能标为论文数值复现。
- NN：训练谱库分箱余弦近邻→近邻分子的指纹→当前候选排序。共享显式二维身份标签与候选得分接口，不能复用上游有结构重叠的划分。
- 首包先分差、最大分数/softmax、熵和温度；后续加普通LR/isotonic、Selective-MSMS强评分与分子级SGR。温度候选 `{1/256,1/64,1}` 仅在dev选择；候选NLL只拟合present，不为absent造正确类别。每次改变候选集重新归一化。
- 必需对照：不看谱图、候选先验、同质量/加合物范围内打乱谱图。所有选择器共用检索器、checkpoint、候选集和原始得分。
- MSAlign在底座、依赖、条款可用后提取冻结特征并训练任务头；公开任务头缺失时不能声称复现完整checkpoint。MolDeBERTa条款未完成时，考虑DreaMS+Morgan变体并如实命名；普通权重不称为data-safe。
- 稳健选择器仅在缺口成立后实现；首选相同特征和容量的L2逻辑模型，以ERM对照group-DRO。多个候选变体按分子归一化权重，不给更多变体的分子更大权重。
- 主工作点 present 接受错误率≤10%、absent FAR≤5%；补充工作点20%/10%。开发内部21点网格固定每方法一个阈值；正式cal只作一次通过/不通过验证，不看结果继续搜阈值。
- 主认证比较稳健选择器与开发选定的最强简单基线。2方法×3种子×U/H×2约束=24个单侧上界，总错误概率0.05。零错误最有利情况下仍至少需要59个已接受present分子和121个absent分子；有错误要求更多。认证失败必须保留失败，修改方法后不能沿用原cal认证。
- 指标分别报告R@1/5/20、MRR、接受率、接受错误率、unknown FAR、有效分母和风险曲线；预测集合覆盖率仅在集合扩展中单列。零接受时风险为未定义，无absent时FAR为未定义。统计假设不自动延伸至D、MCES test、跨库或任意未知比例。
- 必测科学行为：身份/角色隔离、同K和无真值等价体、候选索引、指纹碰撞、确定性同分与排列不变性、零分母、温度/阈值边界、有限样本上界、候选变化后重算置信度，以及checkpoint恢复。

## 阶段、预算与失败处理

以下是投入上限，不是运行预测。GPU小时采用项目独占GPU任务墙钟累计；下载用实际字节累计，磁盘统计项目总量。单GPU任务串行，CPU默认8线程/2 workers；不修改其他环境或管理其他进程。到80%预算评估剩余成本，硬上限前停止。

| 阶段 | 内容与验收 | GPU上限 | 累计下载/磁盘 | 失败处理 |
| --- | --- | ---: | ---: | --- |
| 0 环境材料 | 独立环境、版本/许可/来源记录、确定性完整下载与身份审计 | 0h | 6GB/10GiB | 材料缺失转MLP/NN；依赖冲突仅在项目环境解决 |
| 1 最小闭环 | 先100查询，再单种子MLP/NN/简单选择；恢复、资源标定、封存检查 | 12h（含后续可选MSAlign） | 12GB/60GiB | 优先修数据与指标；不以稳健模块掩盖弱基线 |
| 2 缺口验证 | 同K U/H配对、难度迁移、候选先验/打乱谱图；强简单基线仍有实质失败 | 2h | 12GB/70GiB | 若无可靠缺口，停止方法扩展 |
| 3 方法消融 | 相同容量ERM/group-DRO、去结构/absent、三个训练种子 | 6h | 15GB/80GiB | 改善不稳定或对照复现则停止复杂化 |
| 4 正式验证 | 方法冻结、一次cal、test、D、跨库及统计 | 暂估24h，须依据实测确认 | 25GB/150GiB，进入前重新核定 | cal失败不重用；超预算先集中决策 |
| 5 论文准备 | 数字绑定原始日志、引用可核实、方法/图表/局限与复现入口 | 0h，使用已有结果 | 沿用阶段4 | 结果不足不形成肯定性方法主张，保存负面结论 |

**首个实施包硬上限：2 GPU墙钟小时、6GB下载、20GiB项目磁盘。首十四开发日总上限：20 GPU小时、15GB下载、80GiB。** 阶段1全包不是本次首包一次性训练授权，先完成并验收下面的小闭环。

首包完成条件：

1. 隔离环境可重建；版本、许可、hash和来源已记录。
2. 主数据完整性、身份冲突、跨部分交集和各K保留表产出。
3. 100个预先固定开发查询的候选/身份/得分/标签索引通过检查。
4. 小规模从零MLP、NN、分差与温度流程跑通，checkpoint恢复验证通过。
5. 实测训练/评分吞吐、峰值显存/RSS、数据读取和缓存/保存恢复开销，形成后续单种子预算。
6. calibration/test无模型得分或性能产物，失败/未收敛状态如实保留。

长任务用screen与可恢复checkpoint，保存PID、开始时间、心跳、退出码、日志、模型/优化器/RNG/训练位置。启动不等于完成。标定尽可能测500–1000稳定训练步及1000查询评分；首包规模不足1000时明确样本量并测100查询，外推预算单独标注。

## 前十四日与继续/停止门槛

| 开发日 | 行动 |
| --- | --- |
| 1–2 | 来源与独立环境、约632MB主材料、身份/split/各K保留表、100查询闭环及标定 |
| 3–4 | 单种子MLP/NN和简单选择；材料许可允许才接MSAlign；更新预算预测 |
| 5–7 | 同K U/H、强评分、先验与打乱谱图；cal/test继续封存 |
| 8–10 | 缺口成立后才训练同容量普通/稳健选择器及关键消融 |
| 11–12 | 关键检索器补至3种子；依赖/来源/重复性、误注释案例和成本复核 |
| 13–14 | 仅用开发数据配对分子bootstrap、样本量与继续/停止判断；仍不打开cal/test |

第7日继续条件：100查询、数据边界和单种子MLP/NN可靠；强简单基线在两组预固定候选随机种子上有方向一致的迁移失败或实用接受率不足；数量、顺序、格式和候选先验不能解释。若只有弱检索器失败、区间过宽或工程未稳定，先停止方法开发。

第14日继续条件：同一开发工作点相对最强简单基线接受率增加约5个百分点，或同接受率风险下降约3个百分点；FAR满足目标且区间不显示实质恶化；三种子方向一致，至少10%接受率且不看/打乱谱图对照不能复现提升。这些是内部投资标准，不是正式认证或发表承诺。若普通LR/分差/温度解决问题，停止稳健路线；问题本身不成立则终止方法选题。

跨库优先SpectraVerse v1.0.2，先取约25.2MB元数据并去除与MSG全部角色二维身份交集，再决定是否取约1.378GB MGF。不默认下载大型候选文件；约5000分子是目标而非事实，不称为完全独立或预训练未见。

## 可接续记录与阻塞策略

- `AGENTS.md`固定科学/资源约束；`docs/plan.md`固定批准方案；`docs/evidence.jsonl`逐条保存来源、版本、核查层级及限制；`docs/status.md`更新实际完成和下一步。
- `configs/`存运行输入；`manifests/`存数据/source版本、文件hash、角色与候选清单摘要；完整逐分子/逐候选清单保留于本地artifacts，适合公开的去标识/小型摘要可提交。
- `artifacts/runs/<run_id>/`存完整配置、环境锁、source/data/hash、checkpoint、逐查询原始输出、日志、失败和资源统计；`reports/`仅放可追溯摘要/图表。下载数据、权重、环境、秘密、缓存不提交Git。
- 图表自动从结果文件产生；每项定量论文结论绑定run ID、配置和原始输出。不覆盖失败运行，不混合不同协议的数值。
- 首包无须用户补充的阻塞。账号/条款只影响可选MolDeBERTa分支；不调用付费SIRIUS服务、不取完整PubChem、不装入base。账号、付费、超预算或重大方向变更时才集中询问。
