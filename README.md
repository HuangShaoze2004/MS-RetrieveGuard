# MS-RetrieveGuard

**开放候选库下的质谱分子检索、可靠注释与拒识。**

项目状态：已开始实施首个100查询工程闭环；完整基线、研究缺口和论文数值尚未验证。

**接续入口：[当前状态](docs/status.md)、[已确认计划](docs/plan.md)、[分层证据](docs/evidence.jsonl)。** 下文保留原研究方案；与已确认计划冲突时，以计划及实际运行清单为准。首包上限为2 GPU小时、6GB下载、20GiB磁盘；前两周calibration/test性能封存。

方案版本：`0.1`，更新于 **2026-10-22**。

本项目面向单张 RTX 4090 24GB、使用公开数据、无需新增湿实验的研究条件。优先复用已有检索模型，研究什么时候可以接受分子注释，什么时候应该暂不注释。

## 1. 研究问题与目标

核心问题：

> 当真实分子不在候选库中，而候选库又包含结构相似的分子时，能否减少高置信度误注释，并使选择规则适应候选库的变化？

输入是一张 MS/MS 质谱及一个候选分子集合，输出是以下两种结果之一：

1. 接受排名第一的二维分子结构。
2. 暂不注释，保留排名及不确定性信息以便后续分析。

拒识不等于证明发现了新分子。谱图质量不足、结构歧义、模型失配和候选库缺失都可能导致拒识。

初期聚焦二维连接结构，不声称区分所有立体异构体；不从头预训练化学或质谱基础模型，不依赖新增湿实验，不以单个排行榜分数作为成功标准。

### 1.1 三个研究问题

| 编号 | 问题 | 验证方式 |
| --- | --- | --- |
| RQ1 | 真值缺失及近似结构候选是否造成现有方法的系统性高置信度错误？ | 对同一批查询构造同候选数的真值存在／缺失配对，比较分差、温度缩放和已有选择方法。 |
| RQ2 | 在相同检索模型上，轻量稳健选择器能否优于普通置信度模型？ | 固定检索器与候选得分，只改变选择器及其训练方式。 |
| RQ3 | 选择器和阈值能否迁移到不同候选机制和跨库数据？ | 改变候选数、结构难度、真值缺失比例及数据来源，分别报告已匹配条件与分布偏移结果。 |

### 1.2 创新边界

本项目不宣称首次引入置信度校准、拒识、conformal prediction、困难负样本、候选数分析或真值缺失检测。

拟验证的贡献组合是：现代质谱检索模型上的可复现开放候选库评测、两类错误来源的分离，以及经充分对照验证的轻量稳健选择协议。该组合仍需持续查重和实验证明，不能因尚未找到完全相同的论文就认定存在创新。

### 4.1 主数据：MassSpecGym

入口：[官方数据卡](https://huggingface.co/datasets/roman-bushuiev/MassSpecGym)。

原版 MCES 划分的参考规模：

| 部分 | 谱图数 |
| --- | ---: |

| test | 17,556 |
| 合计 | 231,104 |

这些是原协议的参考数字，不是当前项目已下载后的统计。标准化后的二维分子数、来源分布和实际保留样本数必须从本项目的数据清单重新计算。[原文与协议](https://arxiv.org/html/2602.16507v1)

原候选集合最多 256 个。质量筛选和已知分子式筛选属于不同信息条件，分别报告结果；初期以已知分子式为主，随后增加质量筛选实验。

### 4.2 版本与预训练审计

优先吸收 [MassSpecGym v1.5 审计](https://arxiv.org/html/2606.19624v1)规范。官方v1.5文件已经定位；代码只合并part 1/2，不能仅以版本名视为全部问题已修复。当前固定HF revision为 `d2e86d0c3bd905a6d578c0dd6053ed2bd41f9c2a`，具体文件、校验和及本地修正必须记录。HF容器split名`val`包含全数据，实际划分读取TSV的`fold`列。

需要确认：

- 真实分子与候选分子使用相同的结构标准化与 SMILES 规范化流程。
- 检索身份按标准化后的 InChIKey 前 14 位判断，而不是按 SMILES 字符串相等判断。
- 统一候选去重、候选顺序与同分时的排名规则。
- 普通公开 DreaMS 权重不能直接标记为 data-safe；若无法定位安全权重及过滤清单，披露其预训练暴露审计局限，并保留从零训练的基线。
- MolDeBERTa 的结构预训练暴露与谱图—结构配对标签泄漏是不同问题，分别记录，避免声称所有结构都从未见过。

### 4.3 跨库扩展：SpectraVerse

入口：[SpectraVerse v1.0.2 数据](https://zenodo.org/records/19927403)。

第二阶段计划：

1. 去除与 MassSpecGym 全部 train、dev、calibration、test 的 InChIKey-14 交集。
2. 检查谱图 hash、来源 ID 和近重复谱图。
3. 在剩余数据中确定性抽取约 5,000 个分子；这是目标规模，实际剩余数须先统计。
4. 筛选与模型前处理兼容的离子模式、加合物及质量范围。
5. 固定内部训练、选择器和阈值，先做不重新校准的迁移实验；额外重新校准的结果单列。

SpectraVerse 整合既有公开库，不能仅因名字不同就称其为完全独立外部集或预训练未见数据。

## 5. 数据划分与使用权限

主方案保留官方 MCES train 和 test；将官方 validation 按二维分子身份分为四部分。

| 部分 | 建议比例 | 允许的用途 |
| --- | ---: | --- |
| `train` | 官方 train | 训练检索模型。 |
| `dev_ranker` | 官方 validation 的 15% 分子 | 检索器早停、checkpoint 选择及必要超参数选择。 |
| `fit_selector` | 官方 validation 的 25% 分子 | 拟合选择器；内部划分小验证集选择特征和超参数，并固定阈值网格。 |
| `calibration` | 官方 validation 的 40% 分子 | 固定模型后选择／检查最终接受阈值。 |
| `pilot_dev` | 官方 validation 的 20% 分子 | 前两周开发评估与是否继续投入的判断。 |
| `test` | 官方 test | 协议与方法固定后的最终评估；前两周封存。 |

上述比例是项目设计，并非上游原始划分。所有基线使用同一数据清单，主表结果不能未经说明与使用完整官方 validation 的论文结果直接比较。

规则：

- 同一分子的所有谱图、候选变体及真值存在／缺失版本不跨数据部分。
- 主校准与主要可靠性评估每分子预先固定抽取一张谱图，抽取过程不依赖模型表现。
- 全谱图结果另行报告，以分子作为 bootstrap 聚类单位。
- 分子分组减少重复测量依赖，但不自动证明分子独立同分布；统计保证另行说明假设。
- 在模型拟合前固定划分和随机种子，保存分子级清单及 hash。
- 如做数据量曲线，仅在 train 中按分子抽取 10%／25%／50%／100%，其他数据部分不变。
- 使用 `pilot_dev` 做开发决定后，不将其结果当作独立最终验证证据。

## 6. 候选库与开放场景

### 6.1 定义

**真值存在（present）**：候选集合中存在与真实结构相同的标准化二维连接结构。

**真值缺失（absent）**：按同一标准化流程，候选集合中不存在真实结构的 InChIKey-14 等价体。

训练中未见、但仍存在于候选池的分子属于结构外推／zero-shot 检索，不等于本项目的真值缺失场景。

### 6.2 同候选数的配对构造

第一阶段优先固定 `K=128`：

- present：真实结构 + 127 个合法候选。
- absent：128 个合法候选，全部不与真值二维结构等价。
- 要求原池包含真实结构及至少 128 个其他二维结构，即去重后至少 129 个候选。
- 从共享候选来源构造配对，shuffle 候选顺序，所有模型使用完全相同的候选清单。

不能简单从 256 个候选中删除真值后得到 255 个候选，再让模型利用数量识别 absent 标签。

### 6.3 第一阶段实验因素

| 因素 | 设置 |
| --- | --- |
| 候选数 | `K ∈ {32, 64, 128}`，另保留官方候选池的闭集结果。 |
| 候选组成 | 普通候选；近似结构候选比例较高的压力测试。 |
| 真值缺失比例 | `π ∈ {0, 0.2, 0.5}`，分别报告。 |
| 信息条件 | 已知分子式为主；质量筛选作为扩展。 |
| 数据域 | 内部开发／测试；后续跨库验证。 |

构造要求：

- 原池不足候选的查询不通过重复、填零或任意分子补齐；统一过滤并报告样本保留比例。
- 近似结构压力测试可以使用真值定义离线难度，但不得将真值信息输入模型，也不将压力测试称为自然部署分布。
- 预先固定候选生成种子、来源、结构相似度参数和标签；不按某个方法的结果单独挑选候选。
- K=256 的 absent 场景和大于 256 的扩容需要额外真实合法候选，第一阶段不做。
- 质量筛选部署需要根据前体 m/z 和加合物推测中性质量，不能把真实中性质量作为额外模型特征。

## 7. 检索基线

| 基线 | 目的 | 阶段 |
| --- | --- | --- |
| 分箱谱图 → Morgan 指纹 MLP，使用 ms-mole 检索目标 | 从零训练，验证不依赖外部谱图预训练的结果。 | 必做。 |
| MSAlign 单模型 | 检验现代双编码器检索场景；冻结底座，只训练对齐头。 | 权重、许可与依赖可用时必做。 |
| 最近邻谱图 → 指纹 → 候选排序 | 排除复杂模型不如简单检索的情况。 | 必做。 |
| MSAlign 分数融合 | 强检索基线。 | 研究缺口成立后补充。 |
| 不看质谱的候选先验模型 | 检查结构／来源先验能否解释结果。 | 必做诊断。 |
| 同质量／加合物范围内打乱谱图 | 检查提升是否依赖真正的谱图—结构匹配。 | 必做诊断。 |

不直接计算未经对齐的 DreaMS 与 MolDeBERTa 向量余弦相似度作为双编码器基线：两者不在同一个表示空间。

首轮只训练一个种子。确认流程与缺口后，关键模型在固定划分上增加至三个训练种子。数据划分种子与模型训练种子分别记录。

## 8. 选择与校准基线

所有选择方法共享同一个固定检索模型、checkpoint、候选集合和候选得分，避免将检索能力变化误认为选择器收益。

必要对照：

1. 最大 softmax 概率。
2. top-1 与 top-2 得分差。
3. 检索分布熵。
4. 温度缩放。
5. 普通逻辑回归／isotonic 正确性校准模型。
6. Selective-MSMS 中的强评分和 SGR；有现成工件时增加 ensemble 对照。
7. 本项目的轻量稳健选择器。

若研究目标扩展为返回候选集合，再加入 APS／RAPS 等方法。集合覆盖率保证只在其假设下成立，真值缺失时不可能由候选子集覆盖真值，不能将这种现象表述为 CP 理论被违反。

## 9. 拟议方法

### 9.1 固定检索器

第一版不修改检索模型。检索器输出所有候选的得分与排名；选择器决定是否接受 top-1。

```text
MS/MS 谱图 + 候选集合
        ↓
固定的分子检索模型
        ↓
候选得分、排名与局部结构特征
        ↓
轻量选择器 + 校准阈值
        ↓
接受 top-1 / 暂不注释
```

### 9.2 选择器特征

先使用几十维以内的特征，优先逻辑回归和浅层树模型。

| 类型 | 特征示例 |
| --- | --- |
| 得分强度 | top-1 得分、top-1 与 top-2 分差。 |
| 排名歧义 | 固定温度下的最大概率、归一化熵、接近最高分的候选数量。 |
| 候选结构 | top-1 与前若干候选的 Morgan 相似度、局部结构密度。 |
| 集合信息 | `log(K)`、分子式／质量候选类型。 |
| 谱图元数据 | 峰数、前体 m/z、公开且合法使用的加合物与碰撞能量。 |

结构特征只来自当前候选，不读取真实结构作为输入。相似度所用指纹和维度固定并记录，不能将不同指纹参数的结果混比。

特征组合和正确性预测器本身与既有工作有重叠，不作为独立创新声明。

### 9.3 训练目标

标签为 `z = 1` 当且仅当 top-1 与真实二维结构一致。absent 样本的标签全部为 0。

比较：

- **普通训练**：合并场景，最小化平均正确性分类损失。
- **稳健训练**：按预定义候选场景加权，提高较差场景的权重，检验对未见候选机制的迁移是否改善。

同一分子生成多个候选变体时，按分子归一化权重，不能把变体数量当作新增独立样本。

在人工混合比例上训练的输出先作为选择分数使用，不自动称为部署中的真实正确概率。若报告概率校准，必须指定目标混合比例和校准分布。

### 9.4 阈值选择与统计边界

分开处理：

```text
R_present = P(注释错误 | 接受，真值在库)
FAR_absent = P(接受 | 真值不在库)
```

计划工作点：

- 主要工作点：`R_present ≤ 10%`，`FAR_absent ≤ 5%`。
- 宽松工作点：`R_present ≤ 20%`，`FAR_absent ≤ 10%`。

这些是目标，不是预先承诺能达到的结果。

在选择器、特征、候选生成规则和阈值网格都固定后，使用独立 calibration 数据选择阈值。若对多个预定义场景及阈值同时检查，可以采用同时有效的置信上界并计入多重比较。

calibration 不作为反复反馈的开发集。若查看其结果后再修改特征、训练方式或阈值网格，原认证不能沿用；应使用新的独立校准数据，或事先设计覆盖全部自适应尝试的有效程序。同时认证多个方法时，方法选择也须计入多重比较。前两周早期的临时阈值仅在 `fit_selector` 的内部验证部分拟合，最终方法固定前不读取 calibration 结果。

统计界只在相应抽样、独立性或可交换性条件成立时解释为风险保证。官方 MCES 迁移、候选机制变化和外部数据集不自动满足这些条件，须另行报告经验表现。

对全 absent 的样本，只要接受 top-1 就必然错误；不能要求该组同时具有非零接受率和低 selective risk。该组应控制／报告错误接受率。

若找不到同时满足约束且接受率具有实用价值的阈值，如实报告。零接受率不能包装成有效的高可靠注释系统。

## 10. 指标与统计分析

| 对象 | 指标 |
| --- | --- |
| 检索性能 | Recall@1／5／20、MRR。 |
| present 的选择性能 | 风险—接受率曲线、AURC、目标错误率下的接受率。 |
| absent 的行为 | FAR、未知检测 AUROC，明确检测标签定义。 |
| 混合场景 | 各 `π` 下的总体错误率、接受率和接受正确率。 |
| 正确性概率 | Brier、ECE；注明对应混合比例与定义。 |
| 候选集合方法 | 真值存在时的预测集合覆盖率与集合大小。 |
| 计算成本 | GPU 小时、峰值显存、缓存体积、每谱推理耗时。 |

术语固定：

- **接受率（acceptance coverage）**：接受注释数 / 查询数。
- **预测集合覆盖率（prediction-set coverage）**：预测集合包含真值的比例。
- **接受错误率（selective risk）**：被接受注释中的错误比例。
- **未知错误接受率（unknown FAR）**：真值缺失查询中被接受的比例。

不将这些对象混称为 coverage、置信度或 FDR。若研究有限批次的 FDR，应单独定义和设计验证。

当被接受的 present 样本数为 0 时，接受错误率记为“未定义／不可认证”，不记为 0；此时接受率为 0。若某个评估部分没有 absent 样本，其 FAR 同样记为未定义，并报告分母。

主结果使用固定划分下三个训练种子。按分子做配对 bootstrap，报告区间及各场景有效样本数；所有谱图结果作为补充。AUPRC 如被使用，必须注明真值缺失比例，不能跨比例直接比较。

必要消融：

- 普通选择器 vs. 稳健选择器。
- 去掉候选结构特征。
- 去掉 absent 训练样本。
- 只用分差／温度缩放。
- 不看质谱／打乱质谱。
- 一个候选机制拟合，另一个候选机制评估。

## 11. 单张 RTX 4090 的预算

以下均为规划估算，尚未在 4090 上实测。文献采用的显卡和时间不能通过峰值算力比例直接换算为本项目运行时间。

| 工作 | 初期预算 |
| --- | ---: |
| 特征预计算与缓存 | 8–20 GPU 小时 |
| MLP 检索模型，三个种子 | 3–9 GPU 小时 |
| MSAlign 单模型，三个种子 | 3–12 GPU 小时 |
| 候选评分与重复评估 | 6–16 GPU 小时 |
| 选择器、校准、bootstrap | 主要使用 CPU |
| 排错与重跑余量 | 15–25 GPU 小时 |

上述为原方案历史估算，不能作为实测结果或已授权支出。当前执行上限见已确认计划：首包 **2 GPU小时**，前两周 **20 GPU小时**，根据实测再决定扩大；不包含从头预训练基础模型或大规模超参数搜索。

硬件建议：RTX 4090 24GB；内存 32GB 起、64GB 更稳；SSD 预留 150–250GB。内存与存储数字也是规划值。

实现策略：

- 底座保持冻结。先尝试 microbatch 32，必要时通过梯度累积维持有效 batch。
- 先用 float32 完成小规模验证，再检查混合精度是否改变候选排名和校准结果。
- 分子全局去重后缓存向量，用索引复用，避免按候选列表重复编码。
- 分开记录谱图表征和分子表征的计算时间。
- 不整库下载全部 PubChem 分子和无关工件。
- 将上游存在依赖冲突的特征提取与训练环境隔离。

### 11.1 训练前的 30 分钟标定

1. 热身并记录 torch、CUDA、精度、batch、候选数和机器配置。
2. 测 500–1,000 个稳定训练步的中位／尾部耗时与峰值显存。
3. 测固定 1,000 条查询及不同 K 的评分时间。
4. 分别测少量谱图和去重分子的表征吞吐。
5. 检查 checkpoint 保存／恢复、候选索引和标签一致性。

估算公式：

```text
总训练时间 ≈ 总步数 × 稳定步耗时
           + 验证次数 × 全验证耗时
           + checkpoint 与其他开销
```

特征提取时间、CPU 预处理时间和训练时间分别统计。

## 12. 前两周验证计划

| 时间 | 工作 | 必须产出 |
| --- | --- | --- |
| 第 1–2 天 | 材料、许可、依赖与版本核查；分子分组、标准化、候选索引；小样本端到端检查。 | 数据／模型版本清单、分组清单、100 条查询结果、资源标定。 |
| 第 3–4 天 | 一个种子的 MLP 与可用的 MSAlign；统一模型选择和指标实现。 | 开发集检索结果、训练曲线、实际 GPU 预算。 |
| 第 5–7 天 | 同 K 的 present／absent 配对；分差、温度和普通置信度模型；候选先验诊断；只用开发数据确定临时阈值。 | 现有方法失效的位置、样本量和排除捷径后的证据；calibration 仍封存。 |
| 第 8–10 天 | 缺口成立后训练稳健选择器，与同容量普通模型比较。 | 初步风险—接受率、FAR 和关键消融。 |
| 第 11–12 天 | 增加至三个训练种子；复核谱图依赖、分组和候选来源。 | 稳定性结果、误注释案例、计算成本。 |
| 第 13–14 天 | 在开发集做配对bootstrap、样本量与成本审查；calibration/test继续封存。 | 继续／停止决定及正式验证协议；最终校准仅在方法固定后进行。 |

### 12.1 第 7 天的继续条件

现有强基线确实存在稳定、具有实用影响的错误，而且不能仅由候选数量、格式、顺序或结构先验解释。

材料不可得时先完成 MLP 路线；若连数据协议和最小基线都不能可靠运行，先修复工程，不增加模型复杂度。

### 12.2 第 14 天的内部决策标准

下列标准用于项目筛选，不是发表或统计显著性的承诺：

- 在主要工作点，接受率较最强简单基线提高约 5 个百分点；或在相同接受率下，错误率降低约 3 个百分点且 FAR 没有恶化。
- 改善在三个种子上方向一致，并通过候选先验和打乱谱图对照。
- 保留非平凡接受率；可先将 10% 设为开发阶段的实用目标。
- 统计上界的解释依赖足够的独立校准样本；不能用几个零错误样本宣称可靠。主要工作点应检查被接受校准分子数及实际置信上界。

如果分差、温度缩放或普通逻辑回归已经解决问题，或严格约束下几乎全部拒绝，停止增加复杂模型。重新判断问题或收缩研究范围，不打开正式测试集寻找可报告结果。

## 14. 后续代码实现约定

### 14.1 每次实验记录

- 本项目 commit、上游 commit、配置文件与随机种子。
- 数据版本、分子级 split hash、候选清单 hash。
- 结构标准化、Morgan 指纹参数、打破排名平局的规则。
- checkpoint hash、精度、batch、训练与特征提取环境。
- train／calibration／test 的真值缺失比例及候选场景。
- 实际 GPU 小时、峰值显存、缓存体积和有效样本数。

候选文件顺序不具有标签含义；评估应可验证候选排列不影响结果。

### 14.2 需要的正确性检查

仅对会影响科学结论的行为建立有意义的检查：

- 分子身份及候选等价体去重正确。
- 各数据部分没有分子交集。
- present 包含真值，absent 不包含真值，两种场景的 K 一致。
- 候选向量、候选身份、得分及标签索引一一对应。
- 接受错误率、FAR 与预测集合覆盖率的分母和边界情况正确。
- 校准流程不读取 test 标签；阈值网格在 calibration 前固定。
- 缓存去重前后的向量映射与评分一致。

### 14.3 Git 与资源管理

后续创建 `.gitignore`，排除下载数据、模型权重、表征缓存、虚拟环境、临时日志和认证文件；保留配置、来源清单、hash 及适合公开的汇总结果。

第三方代码、数据和模型分别遵守各自条款。本项目未来选择的许可证不能覆盖上游资源；模型授权也不等于允许公开再分发表征或派生工件。

## 16. 成功与失败的记录方式

只有在同一检索器上超过强简单基线、结果不依赖候选捷径、并在多个场景保留实用接受率时，才进入完整论文实验。

如果收益消失、统计约束不可用或材料不可复现，应保存失败原因、配置和结果。这些记录用于决定下一步，不为维持既定选题而堆叠复杂模块，也不承诺任何期刊分区或录用结果。
